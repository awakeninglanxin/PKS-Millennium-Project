## 二、数据流

```
app.py get_data()
 ├─ 分形: gen_synthetic_panel() 或 fetch_tdx_panel() → build_cjr_timeline() → alert_engine()
 └─ 传统: analyze_traditional() → fetch_index_kline("sh000001") + 指标计算 + 预警
         ↓
json.dumps → 模板渲染（Jinja2 + ECharts 5 CDN）
```

**缓存**：`CACHE` 字典，TTL 3600 秒（1 小时）；刷新页面若未过期直接读缓存，`/api/data?force` 可强制重算。

## 四、接通通达信真实数据（分形面板）

1. 修改 `app.py` 顶部：`TDX_MODE = "tdx"`
2. 实现 `fetch_tdx_panel()`：

```python
def fetch_tdx_panel():
    from tdx_connector import get_kline   # 通达信MCP 或 mootdx
    panel = {}
    for code in hs300_codes:              # 沪深300权重股列表
        k = get_kline(code, period="day", count=500)  # 前复权
        close = np.array([r[4] for r in k])
        panel[code] = np.diff(np.log(close))          # 对数收益率
    return panel
```

3. 重启服务即可用真实 A 股面板跑簇跳率

## 六、维护要点

1. **前端图表必须 try-catch**：7 个图表逐图包裹（v1.1.1 教训——单图异常不得拖垮整页）
2. **ECharts 初始化时机**：必须在 `window.onload` 后延迟 50ms（否则宽度计算错误出框）
3. **JSON 序列化**：numpy int/float 需转 Python 原生类型（v1.2 教训——`default=lambda` 处理 `np.integer`）
4. **数据字段完整性**：后端返回的每个字段前端都会用到，改动契约需同步（v1.1.1 教训——漏 `open` 字段导致 K 线崩溃）
5. **改 JS 后验证大括号平衡**：`js.count('{') - js.count('}') == 0`

## 七、故障排查

| 症状 | 原因 | 处理 |
|------|------|------|
| 页面 500 | JSON 序列化失败 | 检查 numpy 类型转换 |
| K 线无曲线 | 缺 `open` 等字段 | 核对 `analyze_traditional` 返回 |
| 图表出框/空白 | ECharts 初始化过早 | 确认 onload 延迟渲染 |
| 传统区无数据 | 腾讯 API 网络失败 | 检查网络，`trad_ok` 会降级显示 |
| 簇跳率全高 | 用了旧 Ward 聚类 | 确认使用 AnchorClusterer |
